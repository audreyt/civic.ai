# Deterministic conference sensemaking and report replay

The two conference views share one immutable Polis export:

- `/conference/sensemaking/` derives its interactive maps and rankings directly from the checked-in snapshot.
- `/conference/report/` renders checked-in bilingual narrative artifacts generated from evidence derived from that same snapshot.

The site build never contacts Pol.is, GitHub, Ollama, or another model service. A normal build is offline and fails closed if any source or generated byte differs from its manifest.

## Guarantees

There are two distinct replay guarantees:

1. `bun src/cli.mjs verify` lets anyone reproduce the evidence and report HTML from the checked-in snapshot and narratives without a model. It checks every input and output SHA-256 value.
2. `bun src/cli.mjs regenerate` repeats the local model inference twice per locale, sequentially at batch size one. It writes nothing unless the two canonical JSON results for each locale are byte-identical.

The committed artifacts remain the publication guarantee. Model inference is an auditable derivation step, not a request-time dependency.

## Canonical snapshot

`../_data/polis_care_snapshot/manifest.json` identifies the only input snapshot used by both views. The current snapshot is:

```text
snapshot  39b1eed77ad2caed03c11d38b7f5730b5008f9df14e4c7617dc3b2854b740db0
upstream  b1cce6f7761871e51729859600f6b92b3c59b3d7
export    r2jstrdchy3udbrf8arjx
timezone  Europe/London
```

Europe/London is explicit because this deliberation took place at Rhodes House, Oxford. Locale and timezone are independent: the English and Mandarin pages display the same instants in the event-local timezone.

The snapshot contains these unmodified Pol.is flat files:

- summary
- comments
- votes
- participant votes
- comment groups

The snapshot manifest records each filename, byte length, and SHA-256 digest. `_data/polis_care_deliberation.js` verifies those values before deriving anything. It rejects missing timestamps, uses stable ID tie-breakers, fixes source group IDs `0`, `1`, and `2` to display groups `A`, `B`, and `C`, uses the official comment-group counts, and canonicalises derived floating-point values.

The source summary says that 46 voters were in the conversation, while the participant export has 45 explicit group assignments: A has 17, B has 21, and C has 7. The report preserves both facts rather than silently making them add up.

## Verify and build without a model

From the repository root:

```bash
vp install
vp run sensemaker:test
vp run sensemaker:verify
vp build
```

`vp run sensemaker:verify` performs all synchronization checks. If the Polis snapshot changes without regenerated narratives, or any prompt, translation, narrative, report, or manifest byte changes independently, verification fails. CI runs the package tests and this verification before building.

The root build then regenerates both static endpoints from the verified artifacts. Neither Ollama nor network access is needed.

## Refresh the Polis source

A snapshot update must name an immutable 40-character upstream commit. Never refresh from a branch name:

```bash
vp run polis:refresh -- --commit <upstream-commit>
```

The refresh script downloads all five files, preserves their bytes, and creates a deterministic manifest. It contains no refresh timestamp, so rerunning it against the same commit produces the same snapshot ID.

After a refresh, the report verification and site build intentionally fail until the narrative artifacts have been regenerated from the new snapshot.

## Replay local narrative inference

### Prerequisites

Run an Ollama server and install a schema-capable local model. The accepted artifact was produced with:

```text
Ollama       0.32.1
model tag    gemma4:12b-it-qat-mtp
model digest 77136510022ab8b4240a9e4d4094e74de16e638acecde7fcd670c123eb15b44e
family       gemma4
parameters   11.9B
quantisation Q4_K_M
```

The tag is not an identity: the full digest in `generated/manifest.json` is authoritative. This custom model is not available from the public Ollama registry under that bare tag. Exact third-party re-inference therefore requires access to the recorded model artifact. Without it, anyone can still verify and rebuild the committed report bytes; another schema-capable Ollama model can generate a new candidate, but that is a new provenance record rather than an exact replay of this one.

Select a different local model or server only when intentionally creating a new candidate:

```bash
SENSEMAKER_MODEL=<ollama-tag> \
SENSEMAKER_OLLAMA_URL=http://127.0.0.1:11434 \
vp run sensemaker:regenerate
```

For the recorded model on the default local server:

```bash
vp run sensemaker:regenerate
```

Each locale uses:

```text
stream       false
think        false
JSON schema  strict
temperature  0
top_k        1
top_p        1
seed         0
num_ctx      8192
concurrency  1
repetitions  2 per locale
```

Generation order is English run one, English run two, Traditional Mandarin run one, Traditional Mandarin run two. Dynamic batching is not used. The command compares canonical JSON after each pair and aborts before writing if either pair differs.

## Review and publish a regenerated report

After successful inference:

```bash
vp run sensemaker:test
vp run sensemaker:verify
vp build
```

Review these files before accepting the change:

- `generated/narrative.en.json`
- `generated/narrative.zh-tw.json`
- `generated/report.en.html`
- `generated/report.zh-tw.html`
- `generated/manifest.json`

The model writes qualitative prose only. It is prohibited from writing digits, percentages, group sizes, markup, or citation syntax. Statement IDs are locked by the accepted baseline and must be identical across languages. The deterministic renderer adds all counts, percentages, evidence links, group sizes, charts, and snapshot provenance directly from canonical evidence.

`source/accepted-baseline.json` is transparent editorial steering. Supported human-reviewed wording is retained instead of asking a model to gratuitously paraphrase it. `source/translations.zh-tw.json` contains the reviewed statement translations used by both the evidence package and Mandarin report.

## Files

```text
prompts/                         Localised model instructions
source/accepted-baseline.json    Reviewed prose and locked evidence IDs
source/translations.zh-tw.json   Reviewed statement translations
generated/evidence.json          Canonical model and renderer evidence
generated/narrative.*.json       Accepted model outputs
generated/report.*.html          Deterministically rendered report bodies
generated/manifest.json          Source, prompt, model, runtime, and output hashes
src/lib.mjs                      Evidence, inference, validation, rendering, verification
src/cli.mjs                      extract, regenerate, and verify commands
tests/replay.test.mjs            Offline synchronization and grounding tests
```

`polis-report.md` and `tw-polis-report.md` contain only the `astro:polis-report` marker. `_data/polis_report.js` verifies the generated manifest and supplies the matching locale at build time. The build refuses to combine a report with a different sensemaking snapshot.
